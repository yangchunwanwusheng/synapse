# SYNAPSE 演示视频 · 录制与运行说明

> **一句话**：在 openEuler 终端跑一条命令，自动播放约 4 分钟演示动画，配合 OBS 录屏即得演示视频。
> 全程无音、真实命令真实执行、数字全部来自 77 次真实实验。

---

## 1. 演示方案：纯终端动画 + 真实命令

**为什么不用 HTML/浏览器？**
- SP3 目标机是 **headless 服务器**（无桌面、无浏览器、无 X11），装图形栈不稳且偏离 openEuler 真实性。
- 纯终端方案**最能体现 openEuler 真实性**——`uname -a`、`uv run synapse smoke` 都是真实在 openEuler 上跑的，评审一眼信服。

**核心文件**：

| 文件 | 作用 |
|---|---|
| `scripts/demo_play.py` | 终端动画引擎（ANSI 彩色 + 真命令 + 数字滚动 + ASCII 图表） |
| `scripts/demo_record.sh` | 录制包装脚本（环境自检 + 倒计时 + 启动） |
| `scripts/_gen_demo_data.py` | 从真实 run 生成 `dashboard/data.json` |
| `dashboard/data.json` | 演示数据（全部来自 `runs/` 真实实验） |

## 2. 录制流程（5 步，约 5 分钟）

### 步骤 0：环境准备（一次性，已完成）
```bash
cd ~/synapse
# uv 已装、依赖已 sync、.env 已配、smoke 已 PASS（本次会话已全部完成）
# 验证：python3 scripts/_gen_demo_data.py   # 应输出 "真实实验数：77"
```

### 步骤 1：打开终端，调好字体
- 终端字体调大到 **16-18pt**，等宽字体（推荐 **DejaVu Sans Mono** 或 **Noto Sans Mono CJK SC**，后者中文不乱码）。
- 终端**全屏**，建议分辨率 **1920×1080**。
- 背景设为**黑色/深色**（动画配色按暗底设计）。
- 终端尺寸 **至少 100 列 × 30 行**（脚本会检测提示）。

### 步骤 2：打开 OBS，配置录制源
- 安装 OBS（openEuler：`dnf install obs-studio`；或 AppImage）。
- 新建场景，录制源选：
  - **屏幕捕获**（录整个屏幕，最简单），或
  - **窗口捕获**（只录终端窗口，更干净）。
- 设置：分辨率 1920×1080，**30fps**，输出格式 mp4，输出目录设好。
- **不要**勾选音频（全程无音）。

### 步骤 3：启动录制脚本
```bash
cd ~/synapse
bash scripts/demo_record.sh
```
脚本会：
1. 自检环境（openEuler / python3 / uv / 数据）
2. 提示你「现在去 OBS 点开始录制」
3. 等 30 秒或你按回车
4. 3-2-1 倒计时（给你切回 OBS 的时间）
5. 自动播放动画

### 步骤 4：在 OBS 点「开始录制」
- 看到 `3-2-1 倒计时` 时，切到 OBS 点开始录制。
- 然后切回终端看动画自动播放（约 4 分钟）。

### 步骤 5：动画结束，停止录制
- 终端显示 `✓ 演示完成` 后，回 OBS 点「停止录制」。
- 视频文件在 OBS 输出目录。

## 6. 应急预案

| 问题 | 对策 |
|---|---|
| OBS 装不上 | openEuler 可用 ffmpeg 录屏：`ffmpeg -f x11grab -s 1920x1080 -i :0.0 -r 30 out.mp4`（需 X 环境） |
| 终端字体小/看不清 | 调大终端字体到 18pt；或换 `--no-anim`（定格更清楚） |
| 数字滚动录出来有多行 | 用 `--no-anim` 关闭滚动（直接显示终值） |
| `uv run synapse smoke` 失败 | 脚本会提示；可先 `uv sync` 装依赖；或用 `--dry` 跳过真命令（预录的输出也可展示） |
| 总时长想调整 | 改 `demo_play.py` 的 `scenes` 列表里各镜头的 `dur` 值 |
| 动画在某镜头卡住 | `Ctrl+C` 中断，重跑 |
| 想换数据 | 改 `dashboard/data.json`，或重跑 `python3 scripts/_gen_demo_data.py` |

### 中文乱码排查（重要）

脚本已强制 UTF-8 输出（`demo_play.py` 启动时设 `PYTHONIOENCODING=utf-8` + `stdout.reconfigure`，`demo_record.sh` 导出 `LANG/LC_ALL`）。若**录制时仍出现中文乱码/方块/问号**，按以下顺序排查：

1. **终端编码**：确认终端模拟器设置为 **UTF-8**。
   - GNOME Terminal /Konsole：菜单 → 编码 → Unicode(UTF-8)
   - Windows Terminal：settings.json 里 `"profiles" → "encoding": "utf-8"`
   - Xshell/SecureCRT：会话属性 → 终端 → 编码 → UTF-8
2. **终端字体**：中文字体缺失会显示方块（不是乱码，是缺字）。
   ```bash
   dnf install -y google-noto-sans-cjk-ttc-fonts wqy-zenhei-fonts
   # 然后在终端偏好设置里选 "Noto Sans Mono CJK SC" 或 "WenQuanYi Zen Hei Mono"
   ```
3. **locale 环境**（SSH 登录时常见）：
   ```bash
   locale        # 看 LANG/LC_ALL 是否为 zh_CN.UTF-8 或 C.UTF-8
   # 若为空或 POSIX，手动设：
   export LANG=zh_CN.UTF-8
   export LC_ALL=zh_CN.UTF-8
   # locale -a 里没有 zh_CN.utf8 时装：
   dnf install -y glibc-langpack-zh
   ```
4. **SSH 客户端编码**：从 Windows SSH 到 openEuler 时，Windows 客户端默认 GBK，需改成 UTF-8，否则传输中转码会乱。
5. **自检命令**（录制前跑一行确认）：
   ```bash
   python3 -c "print('协作即压缩 · 越用越省')"
   ```
   能正常显示中文 → 环境没问题；显示乱码/方块 → 按上面 1-4 排查。
