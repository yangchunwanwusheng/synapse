# 工程化基线

## AF_UNIX 控制面探针

Issue #4 引入的控制面限定为 Linux/openEuler 上的 `AF_UNIX + SOCK_STREAM`。消息采用
4 字节网络序长度前缀，`transport_bytes` 统计前缀与载荷的真实帧长；它与应用层
`header_bytes + text_bytes + nontext_bytes` 逻辑口径分列，不以逻辑字节冒充内核传输量。

### 已验证边界

- 长度前缀 framing，能够从流式分块中恢复消息边界；
- 并发 `send` 串行化，前缀和载荷不会交错；
- 连接、发送、接收与 `accept` 超时会转为显式 `TransportTimeout`；
- `sendall` 超时可能留下半帧，发送端会立即关闭已失步连接，后续发送显式失败；
- 对端不存在、崩溃/关闭、半帧截断、超限帧均显式失败；
- `close()` 可重复调用，关闭后发送/接收不会静默成功；
- 演示探针覆盖握手、能力发现、路由、关闭全链路。

### 不承诺的能力

本实现不是跨平台 IPC 声明，也不包含背压策略与自动重连。上述两项保留为 P1 后续；
调用方必须自行决定队列上限、重试预算和幂等语义。

### V3-02 对账提醒

当前 `Scheduler + UnixSocketTransport` 已测试 `transport_bytes = 4 + len(wire)`，即按
真实帧长计量；`InProcessTransport` 不产生 4 字节 socket framing。V3-02 落地后仍须按
其最终口径补齐 `transport = Σ帧长`、`logical = Σ(header + payload)` 的组合对账，当前
`Scheduler.send()` 返回的本地 Agent 仅表达路由意图，不代表远端已接收或处理。
