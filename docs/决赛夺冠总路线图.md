# SYNAPSE 决赛夺冠总路线图

> 版本：2026-08-26 v1  
> 目标：在完整满足 M1–M11 的前提下，以一个不可替代的系统机制、一个真实的操作系统数据平面和一套经得起追问的证据链冲击冠军。

## 一、冠军命题

SYNAPSE 不应被讲成“又一个带向量库的多 Agent 框架”，也不应靠协议名词数量取胜。唯一主命题应锁定为：

> **共享记忆不是协作后的仓库，而是接收端的边信息；当系统只传递接收方无法预测的语义残差，多智能体通信会随共同经验增长而持续收缩，并由校验回退保证有损传递不产生静默错误。**

这条命题把赛题三根主轴压成一条因果链：

`共享记忆增长 → 接收方预测增强 → 条件语义残差减小 → 通信成本下降 → 漂移时残差反弹 → 触发失效与安全回退`

评委最终应记住的不是 VLC、CNR、ToM 等缩写，而是三个可复述的事实：

1. **越协作越省**：历史不是额外负担，而是下一轮的压缩先验；
2. **只传不知道的部分**：从完整文本/向量传输升级为条件增量传输；
3. **敢压缩也敢回退**：质量不满足阈值时自动升级传输档位，不允许静默损坏。

## 二、当前真实盘面

### 2.1 已经具备的冠军资产

- 结构化消息、能力协商、四类 Agent、text/synapse 双模式和 CodeAct 已形成源码闭环；
- 条件残差、CAS 句柄、VLC 校验、共享记忆检索与演化构成差异化机制；
- HotpotQA、MuSiQue、CoQA 与受控序列已有真实 API/真实数据结果；
- 已有因果消融、负例、漂移、受损注入和跨任务收缩证据，不只是单张效果表；
- 说明书、PPT、视频、架构图和实验记录资产齐全，叙事基础明显强于普通功能堆叠型作品。

### 2.2 决赛前必须正视的硬伤

本轮源码审计发现：

- `Scheduler.send()` 仍是进程内路由骨架，源码注释明确写着“不做真正异步投递”；
- 当前 `CAS` 是进程内 `dict[str, bytes]`，尚不是跨进程共享内存数据平面；
- 源码中没有实际 `faiss`、Socket、共享内存或 eBPF 路径，但根 README 已出现“提供共享内存跨进程后端与 faiss 后端”的完成态描述；
- 远端仓库没有 CI，且源码包曾因缺少 `README.md` 无法安装；该安装阻塞已于本轮修复；
- 大量设计、实验和分析文件仍处于未跟踪状态，远端仓库不是完整的事实来源；
- 主结果中仍混有小样本 exploratory 结果，部分强表述需要更大样本和多 seed 支撑；
- 公开同赛题项目已经把 Socket、共享内存、eBPF 与 Web 看板作为竞争卖点。即使其实现质量未核验，这也是评委预期正在被抬高的明确信号。

因此，决赛破局不是继续添加概念名，而是补齐一条真实的 Linux/openEuler 系统路径，并把已有算法优势放到真实进程边界和真实系统指标上验证。

## 三、夺冠技术架构：SYNAPSE Fabric

### 3.1 控制面、状态面、记忆面三平面

```text
Agent 进程
   │  结构化控制消息：动作、参数、能力、句柄、校验、租约
   ▼
Control Plane：AF_UNIX / Socket + CNR + 调度 + 背压
   │  只传轻量句柄
   ▼
State Plane：SharedMemoryCAS / memfd + 残差包 + VLC
   │  读写统一 MemoryUnit 与预测基
   ▼
Memory Plane：持久化存储 + 混合检索 + 巩固 + 版本/失效
```

核心不是为了“使用共享内存而使用共享内存”，而是形成可量化的系统分工：

- Socket/AF_UNIX 负责可靠、小体积、可观察的控制消息；
- 共享内存负责大状态的零拷贝或少拷贝交换；
- CAS 句柄负责内容寻址、去重和跨消息复用；
- 残差编码负责从源头减少需要进入数据平面的信息；
- 共享记忆同时提供检索内容和解码边信息；
- VLC 与租约/世代号负责发现语义失真、脏句柄和过期预测基。

### 3.2 第一创新：记忆条件语义传输

保持现有“条件率失真编码”作为唯一头牌，但把机制从进程内实验搬到真实传输接口：

- 建立 `Transport` 接口，至少有 `InProcessTransport`、`UnixSocketTransport`；
- 建立 `BlobStore` 接口，至少有 `MemoryCAS`、`SharedMemoryCAS`；
- 句柄至少包含 `backend / object_id / generation / length / checksum / lease_expiry`；
- 发送端根据接收方能力与预测基选择 text、embedding、residual；
- 接收端校验句柄完整性与语义重构，失败时重新协商并回退。

### 3.3 第二创新：通信成本即漂移传感器

现有残差反弹结果应升级为运行时机制，而不只是一张实验图：

- 对每个 Agent 对、任务族和记忆原型维护残差 EWMA 与分位数基线；
- 残差突增时标记预测基疑似过期，降低其复用权重；
- 连续越界时触发 CNR 重协商、提升传输档位或请求全文；
- 将“发现漂移—失效旧基—安全回退—形成新基—再次收缩”做成现场演示闭环。

它的叙事价值在于：SYNAPSE 不额外部署一个漂移模型，通信系统自身的“惊讶度”就是健康信号。

### 3.4 第三创新：可验证自适应传输

当前三档选择主要由相似度阈值驱动。决赛版本应显式最小化端到端代价：

`cost = wire_bytes + α·latency + β·decode_cpu + λ·quality_risk`

每种传输档位维护在线估计，先以确定性规则实现，再考虑轻量 bandit。必须设置质量护栏：任何自适应策略都不能绕过 VLC，也不能用少做任务换取“节省”。

## 四、实验必须从“效果表”升级为“因果证据链”

### 4.1 主实验矩阵

至少比较五档，逐层回答“收益来自哪里”：

1. Text Full Context；
2. Structured JSON，但仍传全文；
3. Structured + 完整 embedding；
4. Structured + residual，无共享内存；
5. Structured + residual + SharedMemoryCAS + memory prior（完整 SYNAPSE）。

主要数据集继续使用 HotpotQA、MuSiQue、CoQA；机制外部效度再补一个真实连续任务族。主结果建议不低于 `N≥30 × 3 seed`，若资源允许将关键数据集扩到 `N≥100`。所有阈值、主指标和停止规则在运行前写入实验 manifest。

### 4.2 指标分四层

- **任务质量**：F1/EM、成功率、配对差值与置信区间；
- **通信**：消息数、文本 token、控制面字节、数据面字节、去重字节、回退率；
- **系统**：端到端 p50/p95、CPU 时间、RSS、上下文切换、系统调用、拷贝次数或其可观测代理；
- **学习效应**：命中率、预测相似度、残差轨迹、漂移检测延迟、失效后恢复轮数。

结论必须同时满足“省通信”和“质量护栏”。不能再用“CI 含 0”直接写成“严格非劣”，除非预先设置非劣界并证明置信区间下界不越界。

### 4.3 四个评委最难反驳的演示实验

1. **冷启动到暖启动**：同任务族 10 轮，残差与通信量现场收缩；
2. **清空记忆消融**：相同序列不再收缩，证明收益不是任务天然重复；
3. **突然漂移**：残差反弹，旧预测基失效，VLC 回退，随后重新收缩；
4. **真实进程边界**：同一负载在全文 Socket、完整 embedding、残差 + 共享内存三种路径下比较字节、延迟和 CPU。

## 五、评分维度作战表

| 评分维度 | 目标 | 决赛证据 | 主要风险 |
|---|---:|---|---|
| 通信效率 25 | 23+ | 多数据集 token/字节节省；五档消融；真实进程边界 | 只报百分比、不报基线规模与质量 |
| 状态传递创新 20 | 19+ | 条件残差 + SharedMemoryCAS + VLC + 自适应档位 | 共享内存仍停留在文档声明 |
| 记忆复用 20 | 18+ | 记忆作为检索资产和解码边信息；清空消融；漂移失效 | 把普通 RAG 命中包装成核心创新 |
| 系统完整性 20 | 18+ | 四 Agent 多进程、背压/超时/租约、10+ 轮、openEuler CI | 只有 happy path 和进程内函数调用 |
| 实验验证 15 | 14+ | manifest、逐项结果、配对统计、多 seed、失败注入 | 小样本结果混入主结论 |

目标总分不是靠自评分达到 95，而是让每一分都有现场可运行、仓库可定位、结果可复查的证据。

## 六、答辩叙事：七幕而非功能清单

1. **冲突**：Agent 越多、历史越长，文本通信越昂贵；传统系统没有利用“彼此已经知道什么”。
2. **洞察**：多智能体通信是带接收端边信息的条件编码问题。
3. **机制**：共享记忆预测已知部分，只传惊讶残差；控制面与状态面分离。
4. **可靠性**：有损不是赌运气，VLC、世代号和回退把错误显式化。
5. **系统性**：四个真实进程在 openEuler 上经 Socket + 共享内存协作，指标来自运行时而非估算。
6. **证据**：冷→暖收缩、无记忆不收缩、漂移反弹后恢复、真实数据质量守恒。
7. **升华**：SYNAPSE 让“经验”第一次同时成为知识资产、解码先验、压缩器和健康传感器。

现场演示应采用一条可重复录屏的黄金路径，不依赖临时网络：离线/本地模型数据用于核心机制，真实 API 结果作为已落盘证据展示。

## 七、相对时间表

### T-21 至 T-15：真实性与系统底座

- 完成 Claim—代码—测试—产物审计，删除或降级所有超前表述；
- 落地 CI、分支保护、Issue/PR 流程和远端资料分层；
- 完成 Transport/BlobStore 接口与跨进程 SharedMemoryCAS 最小闭环；
- 在 openEuler 容器内跑通 4 Agent 多进程 10 轮。

### T-14 至 T-8：创新闭环与主实验

- 完成自适应档位、租约/世代、漂移失效和安全回退；
- 冻结主实验协议并运行多 seed；
- 产出统一 result schema、自动聚合表和证据索引；
- 完成 Socket/full embedding/residual/shared-memory 五档对比。

### T-7 至 T-3：答辩产品化

- 完成实时看板：消息流、档位、残差、命中、回退、延迟；
- 用最终数据更新说明书、README、PPT，不手工改数字；
- 完成 3 轮不同机器的全新环境复现；
- 建立 30 个尖锐问题的答辩题库，重点准备“是否只是 RAG”“共享内存是否真实”“F1 是否牺牲”“为什么属于操作系统赛题”。

### T-2 至现场：冻结与演练

- 只修 P0/P1 缺陷，不再增加新机制名；
- 固化 release tag、容器镜像摘要、离线数据与演示录像；
- 双人交叉演示，记录每次耗时和失败点；
- 准备无网络、API 不可用、看板失效三套降级方案。

## 八、明确停止做的事

- 不再增加不能用一张因果图说明的新缩写；
- 不再把可选依赖写成已实现后端；
- 不再用 N=3 的漂亮数字充当主结论；
- 不再把普通 Web 看板当创新本体；
- 不再用“黑盒首创、唯一”等不可检验绝对表述；
- 不再让说明书、PPT、README 和代码各自维护一套数字；
- 不为了“操作系统感”堆技术名词，所有 Socket、共享内存、eBPF 都必须对应明确问题与指标。

## 九、决赛发布门槛

- [ ] M1–M11 每项都有源码位置、测试和演示步骤；
